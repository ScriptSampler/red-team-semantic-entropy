# Equivalence audit — annotator protocol

Owed item **B5** (Limitations, "Equivalence is certified automatically, not by humans").
This protocol is **pre-registered**: fix it before opening the sheet, and log any amendment
with a timestamp in §9. If you change the decision rule part-way, everything already
annotated under the old rule must be re-annotated.

Sheets are generated by `scripts/prepare_equivalence_audit.py`; the sampling design,
provenance hashes and stratum sizes are in `results/equivalence_audit_design.md`.

## 1. What you are measuring, and why the wording matters

The attack claims its paraphrases are **meaning-preserving**. Nothing has checked that
except a bidirectional-NLI gate (DeBERTa-large-MNLI), which is *the same model family that
defines semantic entropy in the first place*. You are re-judging that gate's output by
hand, to estimate how often it admits a paraphrase that is **not** equivalent.

This is not the question "do these two mean roughly the same thing?". Nearly every pair in
the sheet will pass that test — they are all fluent rewrites of the same topic, and if you
apply a loose reading you will mark ~100% equivalent and the audit will have measured
nothing. The gate already agrees with the loose reading. That is the whole problem.

### The test you actually apply

> **Substitution test, run in both directions.**
> **Forward:** take *every* answer that would be marked correct for question A. Would each
> of them also be marked correct for question B?
> **Backward:** take *every* answer that would be marked correct for question B. Would each
> of them also be marked correct for question A?
>
> Mark `yes` only if **both** directions hold. If either direction fails for even one
> answer a reasonable person would give, mark `no`.

Two things this phrasing is doing deliberately:

- **"every answer", not "the answer".** Non-equivalence almost never shows up as two
  disjoint answers. It shows up as one question admitting a *strictly larger set* than the
  other. "In which decade…" admits `the 1960s`; "in what year…" does not. Same topic, same
  fact, one-directional failure, **not equivalent**.
- **Both directions.** The gate is nominally bidirectional too, but it is checking
  entailment between question *strings*, not between *answer sets*. Asymmetry is the
  commonest failure mode, and it is invisible if you only check the direction that works.

**Judge the questions, not the model.** You are not asking whether the model answered
well, or whether the answer sounds right. You are asking whether a grader holding the
official answer key for A could use that same key to grade B.

## 2. Procedure per pair

Work through it in this order. Steps 1–3 resolve most pairs in seconds; only ambiguous
pairs need step 4.

**Step 1 — Answer type.** Name the type each question demands: *person / year / decade /
place / title / organisation / count / duration / nickname / two-part*. **If the types
differ, the answer is `no`** and you are done. This one check catches the largest single
class of failures.

**Step 2 — Answer set.** Types match. Now ask whether either question admits answers the
other would reject. Is one set a strict subset? Does one accept a range where the other
demands a point?

**Step 3 — Presupposition and constraint.** Does one question *assert or require*
something the other does not? A dropped qualifier ("which **film director** guested as…")
narrows the search space even when the final answer is unchanged. A dropped constraint is
a meaning change, regardless of whether the answer survives it.

**Step 4 — Only now, `yes`.** If steps 1–3 all pass, mark `yes`.

Use `unsure` sparingly and only for genuine indeterminacy — you cannot tell without
looking up a fact you do not have. `unsure` is **not** for "it's borderline"; borderline
resolves to `no`, because the claim under test is that the pair *is* equivalent and the
burden of proof sits there. Record the reason in `notes`.

### The columns

| column | what to enter |
|---|---|
| `equivalent_yes_no_unsure` | `yes` / `no` / `unsure` — the substitution test above. |
| `answer_could_differ_yes_no` | `yes` / `no` — could a well-informed answerer *legitimately* give a different answer to B than to A? Answer this **independently**; it is not a restatement of the first column. |
| `confidence_1_to_3` | `1` low, `2` medium, `3` high. Confidence in the `equivalent` judgement. |
| `notes` | One phrase naming the shift if you marked `no`: *answer type*, *specificity*, *scope*, *presupposition*, *entity*, *plurality*. Leave blank for a clean `yes`. |

The two label columns come apart, and the gap is the point. A constraint-drop can leave
the answer identical (`equivalent=no`, `answer_could_differ=no`) — and those are exactly
the cases the paper's answer-flip statistic *cannot* see, which is why the Limitations
section calls that statistic a lower bound. Your `equivalent=no, answer_could_differ=no`
count is the first direct measurement of the gap between the two.

## 3. Worked examples

All examples below are real q/q' pairs from **superseded campaigns** (`wk9`, `wk9_def`,
`wk6`, `wk7`), deliberately chosen so that **no pair here appears in your sheet**. Reading
them cannot un-blind anything.

### 3a. Answer-type shift — `no`

> **A:** Whose birthday is celebrated by a public holiday on the third Monday in January in the USA?
> **B:** What public holiday in the United States is observed on the third Monday in January to commemorate a notable figure's birthday?

A wants a **person** (Martin Luther King Jr.). B wants a **holiday** (Martin Luther King Jr.
Day). Step 1 fails. `equivalent=no`, `answer_could_differ=yes`, note *answer type*.

Note how nearly the greedy answer survives: the string "Martin Luther King Jr. Day"
contains "Martin Luther King" and would very likely be graded correct against an alias
list. The automatic status check would see nothing wrong. **This is the failure mode the
audit exists to catch.**

> **A:** In humans, otalgia is the medical term for what?
> **B:** What is the medical term for otalgia in humans?

Reads as a trivial reordering; it is an inversion. A asks what otalgia *means* (earache).
B asks for the term *for* otalgia — which is "otalgia". `no`.

### 3b. Specificity shift — `no`

> **A:** In which decade were ZIP codes introduced in the USA?
> **B:** What year was the United States' ZIP code system first implemented?

`the 1960s` is correct for A, wrong for B. `1963` is correct for both. The forward
direction fails; backward holds. Asymmetry alone is enough. `no`, note *specificity*.

### 3c. Scope addition — `no`

> **A:** How old was Woody Herman when he founded his own orchestra?
> **B:** What year and at what age did Woody Herman establish his own orchestra?

B demands two facts. An answer giving only the age is complete for A and incomplete for B.
One-directional failure. `no`, note *scope*.

### 3d. Presupposition drop that leaves the answer intact — `no`, `answer_could_differ=no`

> **A:** Which film director guested as the FBI Director in The Silence of the Lambs?
> **B:** Who played the role of the FBI Director in The Silence of the Lambs?

A asserts the person is a film director (Roger Corman) — a real constraint that narrows
the space and would make "some character actor" a wrong answer to A but a fine answer to
B. The actual answer coincides, so nothing flips and every automatic check passes. Mark
`equivalent=no` with `answer_could_differ=no`. **This is the single most important cell in
the sheet** and the reason the audit is not redundant with the existing statistics.

### 3e. Entity substitution — `no`

> **A:** Dave Gilmore and Roger Waters were in which rock group?
> **B:** What bands did Dave Gilmour and Roger Waters originally belong to?

Singular *the* group they were in (Pink Floyd) versus plural bands they *originally*
belonged to (different, earlier bands). Scope and plurality both move. `no`.

Watch for near-miss proper nouns generally: a one-word change inside a name — a band, a
film, a title — is a total change of referent even though string similarity is ~99% and
the NLI gate is comfortable with it.

### 3f. Clean equivalence — `yes`

> **A:** Who was the author of 'The Old Curiosity Shop'?
> **B:** Who wrote the novel 'The Old Curiosity Shop'?

Same type, same set, no added or dropped constraint. `yes`, confidence 3.

> **A:** On what date in 1969 did Neil Armstrong first set foot on the Moon?
> **B:** What date in 1969 was significant for being the first time a human, Neil Armstrong, stepped onto the Moon's surface?

Verbose, but the added material is descriptive, not restrictive. `yes`.

> **A:** Which airline is nicknamed 'The Flying Kangaroo'?
> **B:** What is the airline commonly known as 'The Flying Kangaroo'?

`yes`. Do not penalise mere wordiness, register, or hedging ("commonly"). Only penalise a
change in what would be *graded correct*.

### 3g. Genuinely `unsure`

> **A:** Which volcano in Tanzania is the highest mountain in Africa?
> **B:** What is the tallest volcano in Africa located in Tanzania?

A picks out the highest *mountain* in Africa that is a volcano in Tanzania; B picks out the
tallest *volcano* in Africa located in Tanzania. These coincide only if no taller African
volcano exists outside Tanzania — a fact you may not hold. If you cannot settle it, that is
what `unsure` is for. If you *can* settle it, do not use `unsure`.

### 3h. Catch trials

A few pairs are two entirely unrelated questions. They are there to check you, not the
gate. Mark them `no`. If you catch yourself about to mark one `yes` or `unsure`, **stop the
session** — that is the signal that you have drifted into skimming.

## 4. Session hygiene

Fatigue and drift are the main threats to a single-annotator audit, and unlike sampling
error they do not show up in any interval.

- **Cap sessions at 40 pairs.** 123 pairs is 4 sessions; budget ~60–90 s per pair,
  so ~45–60 min per session.
- **Annotate in the file's given order.** It is already shuffled; re-sorting or filtering
  can re-create stratum blocks.
- **Do not look up the pair's origin**, and do not open the key, the campaign JSONLs, or
  `*_design.md`'s strata table mid-audit.
- **Log the start/end timestamp and pair range of every session** in §9. If the leak rate
  differs sharply between early and late sessions, that is drift and must be disclosed.
- **Look things up freely.** Checking who directed Stagecoach is fine and encouraged —
  factual ignorance should produce a lookup, not an `unsure`.

## 5. Computing the headline numbers

Join the filled sheet to the key on `pair_id`. Treat `unsure` as **non-equivalent** for the
primary analysis (the burden of proof sits with the equivalence claim) and report an
`unsure`-excluded sensitivity analysis beside it. Report both; if they disagree materially,
that disagreement *is* a finding.

1. **Validity gate first.** If any catch trial is not `no`, the session it came from is
   void. Report catch-trial performance before anything else. An audit with a failed catch
   trial reports nothing.
2. **Headline — gate false-pass rate on the reported wins.** Among `stratum == win`:
   `p_win = #(equivalent != yes) / n_win`. Report with the finite-population interval
   (`wilson_fpc`, population = the win count in the design manifest) for "among the wins we
   report", **and** the plain Wilson interval for "the gate's rate as a method property".
   They are different claims; §6.
3. **Is the flip statistic a valid lower bound?** Compare `p_flip` against `p_win`. The
   paper's lower-bound framing needs `p_flip` materially **greater**. With n_flip = 13 this
   comparison is nearly powerless — a 13-pair stratum cannot separate 20% from 40%. State
   the comparison and state that it does not settle it.
4. **Selection pressure.** Compare `p_win` against `p_subthreshold`. Higher in `win` means
   the optimiser is *selecting for* gate failures, not meeting them at the base rate. This
   is the closest available substitute for a benign arm and is weaker than one (§8).
5. **The invisible-to-automation count.** `#(equivalent == no AND answer_could_differ ==
   no)` in the `win` stratum. This is the number of meaning changes that **no** automatic
   check in the pipeline could have caught, and it is the most novel quantity the audit
   produces. Report it as a count and a rate.
6. **Report the `unsure` rate and the confidence distribution.** A high `unsure` rate or a
   mass of confidence-1 judgements bounds how much any of the above is worth.

## 6. What this audit can and cannot settle

Be explicit about this in the paper; it is the difference between a defensible disclosure
and an overclaim.

**It can settle:** whether the reported wins contain non-equivalent paraphrases, and how
many. The win stratum is censused (all of them), so for the claim *"of the wins in this
paper, k were not meaning-preserving"* there is **no sampling error at all** — it is a
count, not an estimate. If k > 0, those wins should be withdrawn or re-reported behind a
hand-verified subset. That alone discharges most of what a hostile reviewer is asking for.

**It cannot settle:** the gate's false-pass rate as a general property. For that, these
wins are one draw. A census of 72 with an observed 10% still gives roughly [0.05, 0.19] —
a factor of four. Nothing an annotator does narrows that; only a bigger pool does. See the
n-vs-width table in `equivalence_audit_design.md`.

**It cannot establish inter-annotator agreement.** One person cannot produce a κ between
two people, and §7 must not be described as though it does.

## 7. Agreement from a single annotator

There is no inter-annotator κ available. Four partial substitutes, in descending order of
strength. Report all four; none of them alone is sufficient, and saying so is the point.

### 7a. Test–retest (intra-annotator) reliability — the headline agreement number

`equivalence_audit_round2.csv` re-presents a 30% subsample (37 pairs) with **new pair ids,
an independent shuffle, and the A/B orientation flipped**, so a pair cannot be recognised
by its id, its position, or which column the original sat in.

- **Washout ≥ 7 days.** The only real defence against recall is time. Do not shorten it;
  a 1-day retest measures memory, not reliability.
- Compute, on the 37 pairs: **raw percent agreement**, **Cohen's κ** on the 3-level label,
  and **κ on the binarised label** (`yes` vs `not-yes`).
- **Report the marginal prevalence alongside κ, and report PABAK or Gwet's AC1 too.** If
  ~85% of judgements are `yes`, κ becomes unstable and can look poor at 95% raw agreement —
  the well-known kappa paradox under skewed marginals. Reporting κ alone, on skewed data,
  is misleading in *both* directions.
- **Bootstrap a CI over the 37 pairs.** It will be wide. Print it anyway.
- Any pair that changes label between rounds should be **adjudicated in a third pass** and
  the adjudicated label used in §5, with the flip count disclosed.

State plainly what this is: *test–retest reliability of one annotator*. It bounds how
**self-consistent** the judgements are. It says nothing about whether they are **right** —
a consistently wrong annotator scores a perfect κ.

### 7b. Catch trials — the validity floor

§3h. These are the only part of the design that can detect a rubber-stamping annotator,
which is precisely the failure test–retest cannot see. Report the catch-trial pass rate as
a precondition on everything else.

### 7c. A disclosed strong-LLM-judge as a second rater

The Limitations text already allows "human **or disclosed strong-LLM-judge**". The repo has
a judge validated at 0.93 on the hard discrimination (`results/judge_validation.md`). Run
it over the **same blinded sheet**, with **this protocol's substitution test as its
prompt** — not a generic "are these the same?" — and report human-vs-judge agreement.

Frame it honestly: this is **not** an independent human and **not** an inter-annotator κ.
Two further caveats that must be disclosed if this is used: the judge shares a training
lineage with the systems under test, and its 0.93 validation was measured on *answer*
equivalence, not *question* equivalence — a different task, so the 0.93 does not transfer
unexamined. Where the judge and the human disagree, report the disagreement rate and
inspect every disagreement by hand; do not average them into a single number.

### 7d. Pre-registration and an auditable trail

The decision rule in §1–§2 was fixed before the sheet was opened. Amendments go in §9 with
timestamps. Publish the protocol, the blinded sheet, the key, and the filled labels
together, so a reader can re-judge any pair themselves. With n=1 annotator, **transparency
is doing the work that agreement statistics normally do** — that substitution is legitimate
only if the artefacts are actually published.

### Recommended wording for the paper

> Equivalence was audited by hand by one annotator against a pre-registered bidirectional
> substitution rule, blind to stratum and to attack direction, over a census of all N
> reported wins plus the answer-flip and sub-threshold strata and C catch trials. Because
> only one annotator was available we report intra-annotator test–retest reliability on a
> 30% re-presented subsample (raw agreement A, κ = K, prevalence P) rather than an
> inter-annotator κ, together with catch-trial performance and a disclosed LLM-judge second
> pass. Test–retest reliability bounds self-consistency, not correctness.

## 8. Known gaps in this design

Disclose these; do not let a reviewer find them first.

1. **No benign-paraphrase arm.** The proper control — paraphrases from the same proposer
   through the same gate with the entropy objective switched *off* — does not exist in text
   form anywhere in the cache (the null-control and ablation checkpoints store *moves*, not
   strings), and generating them needs the proposer LLM on the GPU. Without it, there is no
   estimate of what this annotator marks non-equivalent when nothing adversarial happened,
   so `p_win` has no baseline to be compared against. `subthreshold` is a stand-in and a
   weaker one: those paraphrases were still produced by an optimiser trying to move entropy,
   it merely failed. **To close this**, generate benign paraphrases with `se.attacks.proposer`
   (objective disabled), gate them with the same feasibility check, save the surviving
   strings to JSONL, and pass `--benign_jsonl`. The flag exists and currently refuses
   rather than fabricating an arm.
2. **The hide cell was incomplete at snapshot time** — 52 of 80 targets, with
   `scripts/recompute_fair.py --tag _defb` still running. The audit therefore covers the
   snapshot in the manifest, not the finished campaign. When the run completes, generate a
   **top-up batch** with `--exclude_audited results/equivalence_audit_key.csv` so the second
   batch is disjoint; do **not** re-draw round 1, which would discard completed work and
   break the census claim.
3. **Blinding is self-imposed.** One person owns the repository, the key, and the sheet. The
   file layout makes the honest path the easy one; it cannot enforce it. Say so.
4. **The annotator is the paper's author** and is not disinterested. Nothing in this design
   fixes that. It is the strongest argument for 7c and 7d, and for publishing the artefacts.
5. **Typography, and how to open the sheet.** The questions carry real typographic
   characters straight from TriviaQA — curly quotes (`’` `‘`), en dashes, ellipses. The
   CSVs are written as UTF-8 **with a BOM** so a double-click opens correctly in Excel. If
   you see `�` or `â€™`, your reader has guessed the wrong encoding: reopen as UTF-8
   (Excel: *Data ▸ From Text/CSV*, encoding 65001). Do **not** "clean" the text — the
   stimulus must stay byte-identical to what the model was given.
